# 0007 — у каждой повторяющейся работы должна быть измеримая величина

**Дата:** 4 сентября 2026
**Статус:** принято, реализовано в `core/health.py` и миграции 012

## Из чего выросло

Дозаполнение крутило одни и те же объявления по кругу трое суток. Стоило это
пять шестых всех расходов на модель. Ошибок в логе не было ни одной: строка
«дозаполнено 25» при цикле выглядит ровно так же, как при нормальной работе.

Заметили случайно — при проверке кнопки «данные неверны» бросилось в глаза
число вызовов у одного объявления.

Это не единичная ошибка, а класс. Общая форма: работа повторяется, признак
«сделано» выводится из содержимого результата, пустой результат неотличим от
«ещё не пробовали». Ничего не падает, ничего не логируется как ошибка, счётчик
растёт только в кошельке.

## Решение

Три уровня, намеренно независимые друг от друга.

**Отметка о выполнении хранится отдельно от результата.** `llm_at` ставится при
любом исходе обращения к модели, включая «ничего не нашлось». Это чинит
конкретный цикл (решение 0006).

**Жёсткий предел поверх отметки.** `llm_attempts` — счётчик, который только
растёт. Сколько бы флагов ни сбилось, к одному объявлению модель не обратится
больше трёх раз за всю его жизнь. Смысл в независимости: первый уровень может
сломаться от любой правки, второй не зависит ни от чего, кроме самого себя.

**Проверка ожиданий.** У каждой повторяющейся работы есть величина с известным
нормальным значением, и раз в час они сравниваются с ожиданиями:

| величина | ожидание | что ловит |
|---|---|---|
| вызовов модели на объявление за сутки | ≤ 1.5 | цикл дозаполнения |
| расход за сутки против медианы недели | ≤ 3× | он же, со стороны денег |
| размер очереди к модели | ≤ 300 | очередь, которая не убывает |
| часов с последнего собранного объявления | ≤ 8 | молчащий сборщик |
| объявлений в повторной обработке | ≤ 50 | застревание |
| упёрлись в предел попыток за сутки | < 20 | формат, с которым модель не справляется |
| профилей с очередью и без отправок за сутки | 0 | сломанная доставка |
| размер базы | ≤ 500 МБ | рост без границ |

Проверки сформулированы как утверждения о числах, а не как поиск исключений.
Цикл, молчащий сборщик и застрявшая очередь исключений не выбрасывают — их
видно только по величине, вышедшей за ожидаемое.

Отчёт уходит администратору при расхождении, не чаще раза в сутки на каждую
проверку. Полная картина по запросу — команда `/health`.

## Проверка задним числом

Собранная проверка, прогнанная на копии базы за те самые дни, даёт:

```
⚠ вызовов модели на объявление: 3.67 (допустимо 1.5; 858 вызовов на 234 объявлений)
⚠ расход за сутки: $1.752 при обычных $0.534
```

То есть цикл был бы виден в первые же сутки, а не на четвёртые и не случайно.

## Что осталось за границей

Проверки считают по своей же базе. Расхождение между нашим счётчиком расходов и
счётом Anthropic ими не ловится — на сегодня оно 3%, и сверяется вручную.
